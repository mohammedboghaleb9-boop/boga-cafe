## What it is
Website + online shop for BOGA CAFÉ, a whole-bean coffee brand from Oujda (Morocco). B2C and B2B: a cart above the B2B threshold (`settings.b2bThresholdKg`, 10 kg) becomes a quote request.
B2B blends: 250 g and 500 g are paid samples bought like any bag; the 1 kg bag only in a cart above the threshold. Custom Blend: the customer sets origin percentages (total 100).
Stock in kg per origin. Arabic (RTL), French, English. Admin roles owner / manager / staff. No cash on delivery: every order is paid before prep. Delivery covers every Moroccan city (owner 2026-10-22).

## Key decisions and why
- **The database recomputes every order** (`check_order`) and stores what it rebuilt; the browser is not trusted. `tests/sql-parity.test.ts` generates `supabase/tests/parity.sql` (42 orders built by `src/core`) and CI runs it on PostgreSQL.
- **Orders and B2B requests go through the `storefront` function** (Turnstile first, then per-connection and per-phone limits, rebuild from the database with `src/core`, `check_order`, `commit_*` which saves, numbers and queues the messages in one transaction). Card stored off until the CMI callback exists.
- **Turnstile**: the token needs `action` = the route and `hostname` in `TURNSTILE_HOSTNAMES` (Supabase secret; exact names, or one wildcard glued to a dash for the previews). No secret or a Cloudflare test secret = every form refused. The widget is real only in `supabase` mode. **Before launch: remove the preview wildcard (secret and widget), list `bogacafe.ma` and `www.bogacafe.ma` by name.** Real siteverify never seen from here.
- **Rounding matches PostgreSQL** (half up, 1e-9 nudge; stock per origin summed as whole numbers, divided once).
- **Every stock reservation ends**: 48 h unpaid, 120 h after "I paid", counted from the order time; no setting stops it (`expire_unpaid_orders`; locks origins in id order since `20261016180000`, deadlock-tested).
- **"I paid" is a claim, not money**: only the owner marks paid; a paid order ends with a refund, not a plain cancel. Payment methods stay closed until real details exist (`payeeReady`, `invalid_order:payment_details`); Cash Plus = name, city, phone, never a CIN; RIB = 24 digits (check key unverified). The repo is public: bank details only from the Admin.
- **Sales gate**: `settings.salesOpen` (missing = closed) checked at the final write (`commit_order`, `commit_quote_request`); only `set_sales_open` (owner, aal2) changes it. Four layers: UI notice, `storefront` refuses `sales_closed`, both `commit_*`. Opening needs its own approval, after the outbox sender and a delivery test.
- **Delivery**: included weight 3 kg (owner 2026-10-19; the 4th kg is the owner's margin, never a hidden charge; the tariff text at pricing must say 3 kg). A city shown needs a fee > 0. Real fees when the tariff is ready.
- **Data contract**: pages see data only through `src/data/api.ts` and the hooks; `tests/architecture.test.ts` refuses a page importing a backend. The Supabase backend fills the same in-memory `DbState`. Admin saves go through `useAction` (one at a time; busy = `aria-disabled`, keeps keyboard focus).
- **Admin**: Supabase Auth email + password (own client `boga-admin-auth`) then TOTP, mandatory in the database (`is_admin()` needs `aal2`). RLS answers a non-admin with empty rows, not an error, so the role is asked after the reads. Reads: `adminData.ts` (newest 1000 orders/requests). Writes: database functions only (`adminWrites.ts`, `configWrites.ts`), each compared with a version mark (`stale`); API roles have SELECT only on the written tables; who changed what goes to `catalog_changes` / `config_changes` (admin-only), never a public column.
- **Catalog writes**: an id is the address, fixed after creation; a new product/origin starts hidden (origin at 0 kg); a shown product uses shown origins only (`hidden_origin`); texts are trimmed in SQL (`config_trim_*`). `save_payee` trims spaces only.
- **Two builds from one code base** (`scripts/build-target.mjs`, fails closed): empty `VITE_DATA_MODE` = "coming soon", `supabase` = the shop, `demo` = prototype and browser tests. A Workers Builds build of `main` is production whatever `--mode`, built from `.env.workers-preview` only (a dashboard `VITE_` variable stops it). `real-build.mjs` scans every output for demo strings, example names/cities/prices, live project refs; `tests/build-gate.test.ts` runs the real builds.
- **Fallback**: `PRODUCTION_SITE = 'coming-soon'` (one line, then merge) puts the "coming soon" page back; its last deploy is Cloudflare version `60569f1c-e45b-4462-97d1-a194aad80b4e` (`main` `8830180`). Never roll back to an older version (it showed example prices). The coming-soon build ships no `_headers`.
- **Pictures** (PR #32): `scripts/shop-headers.mjs` writes one exact `immutable` rule per hashed file that exists, never `/assets/*` (the SPA fallback would cache HTML for a year); HTML stays revalidated. `ProductVisual` shows its sticker only with the decoded photo (retries, then the name in text); `nearLoad.ts` starts lazy images 1.2 screens early. Measured in Chromium; on a real iPhone the owner reported 2026-10-26: tested on an iPhone, everything fine so far (no detailed log; other iPhones, Safari on Mac, Android, Firefox not covered).
- **Previews**: Version URLs are off (`"preview_urls": false`, pinned by `tests/wrangler-config.test.ts`) because a branch build is the shop on the live database. Dashboard commands: Build `npm run build`, Deploy `npx wrangler deploy`, Preview `env -u WRANGLER_CI_MATCH_TAG npx wrangler versions upload`. `wrangler` is pinned at 4.153.0 (from 4.148.0 on 2026-10-26; its source still publishes custom domains only when `routes` are listed, `wrangler deploy --dry-run` shows none, `npm audit` 0).
- **Sales-closed catalog** (`20261021120000_catalog_showcase`): `listed` flag, `showcase_catalog()` returns display keys only; visitors' table reads are gated on `sales_open()`; the site reads it with `VITE_SHOWCASE=on`. Undo: `supabase/manual/20261021120000_catalog_showcase.unlist.sql`, then `VITE_SHOWCASE` off, then the rollback block.
- **Workflow**: one branch per task; one review pass per slice by the project agents `code-reviewer` / `security-auditor` (`.claude/agents/`, sonnet, read-only: the diff goes in the prompt); CI green; `merge --no-ff` only with the owner's approval. Never deploy from an unmerged branch. No secrets in the repo.
- **Audit rule**: a rule counts as tested only if breaking it makes a test fail (`docs/10-reviews-history.md` section 2).
- **Database changes**: never edit an applied migration. The apply tool times out on DELETE/DROP and renames the version it stamps; such migrations are run by the owner in the SQL Editor (`begin; … commit;`, count check, version recorded by hand; blocks in `supabase/manual/`). Never rerun the history-repair or `catalog_trim` editor blocks.
