# 05 · خطوات البناء (خارطة الطريق)

كل مرحلة لها **مخرجات** و**شرط إنهاء** واضح. المدد تقديرية لمطوّر واحد مع الذكاء الاصطناعي، وتتوقف كثيراً على سرعة الحصول على المعلومات والعقود (خاصة CMI).

```
المرحلة 0  تحضير المعلومات والحسابات        ← يبدأ بالتوازي الآن
المرحلة 1  النموذج الكامل (هذا التسليم)      ✅
المرحلة 2  قاعدة البيانات والخادم الحقيقي    
المرحلة 3  الدفع
المرحلة 4  الإشعارات الحقيقية
المرحلة 5  المحتوى، SEO، الصفحات القانونية
المرحلة 6  الاختبار والإطلاق
المرحلة 7  ما بعد الإطلاق
```

---

## المرحلة 0 · التحضير (مسؤوليتك مع دعمي)

- [ ] الإجابة على الأسئلة المفتوحة في `07-open-questions.md` (المهم منها 5 أسئلة).
- [ ] القائمة النهائية: المصادر (البلد، أرابيكا/روبوستا، المنطقة، درجة التحميص، النكهات، سعر الكيلو)، الخلطات المميزة، خلطات B2B الثلاث (الوصفة + السعر لكل حجم).
- [ ] المخزون الحالي لكل مصدر بالكيلو.
- [ ] جدول أسعار التوصيل من شركة التوصيل المختارة.
- [ ] الشعار بصيغة مصدرية (SVG أو PNG شفاف عالي الدقة) + صور حقيقية للأكياس.
- [ ] الوثائق القانونية وفتح الحساب البنكي المهني وطلب CMI (أطول مسار).

**شرط الإنهاء:** كل البيانات الحقيقية متوفرة لتعويض البيانات التجريبية.

## المرحلة 1 · النموذج الكامل ✅ (تم)

- كل صفحات المتجر بثلاث لغات، الخلطة الخاصة، B2B، السلة بقاعدة 10 كلغ، الدفع في صفحة واحدة، صفحة الطلب.
- لوحة الإدارة بـ 10 أقسام و3 أدوار.
- منطق الأعمال في `src/core` مختبر آلياً (124 اختباراً في المشروع كله، و 28 اختبار متصفح).
- مخطط قاعدة البيانات للإنتاج مع 20 فحصاً على PostgreSQL حقيقي.
- الوثائق.

## المرحلة 2 · قاعدة البيانات والخادم (≈ 2–3 أسابيع)

1. إنشاء مشروع Supabase (منطقة أوروبية قريبة من المغرب) وتطبيق `supabase/migrations`.
2. إدخال البيانات الحقيقية (سكربت استيراد من ملفات `src/data/seed` بعد تحديثها).
3. كتابة **`src/data/supabase/`**: نفس دوال `api.ts` و `hooks.ts` لكن مع Supabase. تفعيلها بـ `VITE_DATA_MODE=supabase`.
4. Edge Functions:
   - `create-order`: تستعمل `src/core/order.ts` ثم `commit_order()`.
   - `sample-request` و `quote-request`: التحقق + Turnstile + حد للطلبات لكل هاتف.
5. تسجيل دخول الإدارة بـ Supabase Auth (بريد + كلمة مرور، وتحقق بخطوتين للمالك) وجدول `admin_users`.
6. رفع الصور إلى Supabase Storage من صفحة المنتج في الإدارة.
7. النشر على Vercel مع نسخة معاينة لكل تعديل.

**شرط الإنهاء:** طلب حقيقي من هاتف يظهر في الإدارة من جهاز آخر، والمخزون يُخصم في قاعدة البيانات.

## المرحلة 3 · الدفع (≈ 1–2 أسبوع بعد الحصول على وثائق CMI)

1. كاش بلوس والتحويل (يعملان مباشرة بعد المرحلة 2): إضافة **رفع صورة الوصل** بدل المرجع النصي فقط.
2. CMI: Edge Function تبني النموذج الموقّع، و`cmi-callback` تتحقق من التوقيع وتحدّث الحالة إلى «مدفوع».
3. الاختبار في بيئة CMI التجريبية ثم الإنتاج.
4. مهمة مجدولة: إلغاء الطلبات غير المدفوعة بعد المدة المحددة في الإعدادات وإرجاع المخزون.

**شرط الإنهاء:** دفع حقيقي بالبطاقة يصل للحساب البنكي الرسمي، والطلب يتحول تلقائياً إلى «مؤكد».

## المرحلة 4 · الإشعارات (≈ 1 أسبوع)

1. ✅ واتساب عبر CallMeBot (الكود جاهز، ينقص المفتاح). WhatsApp Cloud API ترقية لاحقة: الرقم، قالب الرسالة، الموافقة من Meta.
2. Gmail SMTP بكلمة مرور تطبيق.
3. Edge Function `send-notifications`: تقرأ جدول `notification_outbox` وترسل وتعيد المحاولة عند الفشل.
4. (اختياري) رسالة تأكيد للزبون بالبريد/واتساب.

**شرط الإنهاء:** كل طلب وكل طلب عيّنة يصل إلى هاتف الإدارة وبريدها خلال أقل من دقيقة.

## المرحلة 5 · المحتوى وSEO والقانون (≈ 1–2 أسبوع)

1. الصور: الهوية الأساسية **معتمدة ومدمجة** (انظر `08-visual-assets.md`)، والمتبقي صور حبوب كل مصدر وتركيبة الخلطة الخاصة. ثم نصوص المنتجات بثلاث لغات (مراجعة العربية والفرنسية من شخص محلي).
2. الصفحات القانونية: شروط البيع، الخصوصية، التوصيل والإرجاع، الإشعار القانوني.
3. SEO: توليد صفحات HTML مسبقاً، `sitemap.xml`، `hreflang`، صور المشاركة (Open Graph)، روابط `/ar /fr /en`.
4. نافذة الموافقة على الكوكيز، ثم Analytics و Pixels.
5. ✅ الخطوط مستضافة ذاتياً (`@fontsource`)؛ يبقى تحسين الصور (`srcset`).

## المرحلة 6 · الاختبار والإطلاق (≈ 1 أسبوع)

- [ ] سيناريوهات كاملة على الهاتف: كل طرق الدفع، الخلطة الخاصة، طلب فوق 10 كلغ، عيّنة، إلغاء.
- [ ] اختبار الأدوار الثلاثة في الإدارة.
- [ ] تجربة 3 طلبات حقيقية مع المحمّص وشركة التوصيل من البداية للنهاية.
- [ ] نسخ احتياطي لقاعدة البيانات مفعّل، Sentry و UptimeRobot مفعّلان.
- [ ] ربط النطاق، شهادة HTTPS، Search Console.
- [ ] تدريب فريق الإدارة (ساعة واحدة تكفي مع هذا الدليل).

## المرحلة 7 · بعد الإطلاق (حسب الأولوية)

1. **حسابات الزبائن** (كما ذُكر في التقرير): حفظ العناوين، إعادة الطلب، حفظ الخلطات الخاصة.
2. **فواتير PDF** تلقائية مع ICE (مهم لزبائن B2B).
3. **تتبع الدفعات (Lots)** بتاريخ التحميص.
4. ربط API شركة التوصيل (رقم التتبع يظهر للزبون).
5. أكواد تخفيض، اشتراك شهري في القهوة (دخل متكرر).
6. تقارير: المبيعات حسب المنتج/المدينة، الخلطات الخاصة الأكثر طلباً (قد تصبح خلطات رسمية!).

## كيف نعمل على كل قسم وحده

- كل تعديل في **فرع Git مستقل** (مثلاً `feature/checkout-receipt-upload`) → معاينة تلقائية → دمج.
- كل قسم له مجلد (انظر `06-modules.md`)، فيمكن العمل على «الخلطة الخاصة» دون لمس «الإدارة».
- قبل أي دمج: `npm run typecheck && npm test && npm run build`.
