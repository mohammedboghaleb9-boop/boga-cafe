# 09 · كيف تصل الطلبات إلى واتساب و Gmail

محيّنة فـ 2026-10-26. **الوضع: الرسائل كتتسجل، والمرسل ما مبنيش.** بناؤه هو الشرط الأول قبل فتح البيع (`docs/12`).

## 1. اللي خدام دابا

| الطبقة | كيفاش | أين |
|---|---|---|
| **تسجيل الرسالة (الخادم)** | مع كل طلب أو طلب B2B، دالة قاعدة البيانات (`commit_order` / `commit_quote_request`) كتكتب فـ `notification_outbox` (القناة، الحدث، المستلم، الموضوع، النص) **فنفس العملية** اللي كتحفظ الطلب: ما كاين طلب بلا رسالة. الحالة `pending`، وتظهر فلوحة الإدارة (قسم «الإشعارات»، للمالك والمسيّر) | `supabase/migrations/20260927000000_init.sql` (الجدول)، و`20261007080308_order_idempotency_commit.sql` |
| **من طرف الزبون (بلا خادم)** | بعد طلب أو «لقد دفعت» أو طلب B2B، كتبان للزبون بطاقة فيها زرّان: **إرسال عبر واتساب** (كيفتح واتساب على رقم BOGA ‎+212 6 09 03 63 78 والرسالة مكتوبة كاملة) و**إرسال عبر Gmail** (رسالة جديدة لـ bogacafe1@gmail.com). الرسالة كتوصل من رقم الزبون نفسو. | `src/shared/layout/SendToBoga.tsx`، النصوص من `src/services/notifications/templates.ts` |

**حدّ الطبقة الثانية:** إلا سد الزبون الصفحة بلا ما يضغط «إرسال»، الرسالة ما كتوصلش. وهذا علاش المرسل من الخادم ضروري.

## 2. اللي ناقص: المرسل (المرحلة 4)

- **شنو**: دالة Supabase (Edge Function) كتقرا `notification_outbox` (`status = pending`)، وكتبعث لكل رسالة، وكتعلّم `sent` أو `failed` (مع `attempts` و`last_error`)، وتعاود المحاولة. مجدولة (cron) أو كتتشغل عند الإدراج.
- **القنوات**: Gmail (SMTP بكلمة مرور تطبيق) وواتساب (CallMeBot لرقم المالك الآن؛ WhatsApp Cloud API لاحقاً). المستلمون كما هم فالإعدادات (`save_recipients`، للمالك وحده؛ الرسائل للإدارة بالفرنسية: قرار المالك).
- **الأسرار**: فـ Supabase → Edge Functions → Secrets (ماشي فالمستودع ولا فالمتصفح، ولا بـ `VITE_`).
- **حالة التعليق**: معلّق حتى يتوفر عبد الرحيم (عنده الدخول لـ Gmail). ما كاين حتى إعداد Gmail/WhatsApp ولا سر جديد ولا تجربة إرسال.
- **شرط الإغلاق**: رسالة تجربة توصل لـ WhatsApp وGmail من الموقع الحي، وفشل قناة كيبان فاللوحة ويعاود المحاولة.
- **ما يتنقل من `api/_lib/notify.ts`** (منطق مختبر خاص ما يضيعش): تعطيل كل ما يُقرأ كرابط فالنص (`hxxps://evil[.]com`، بلا قائمة نطاقات، والأرقام مثل 0.25 kg ما كتمسّش)، واعتبار واتساب «أُرسل» غير إلا ردّت CallMeBot بتأكيدها (Message queued / sent)، وعدم تكرار نفس الرسالة، وإعادة محاولة الفاشلة. بعد النقل: حذف `api/` و`vercel.json` و`nodemailer` و`tsconfig.api.json` (قرار منفصل بموافقة المالك).

## 3. بقايا `api/notify.ts` (ما منشورة)

دالة Vercel كُتبت للخطة الأولى (قبل اختيار Cloudflare Workers): ما كتخدمش على الاستضافة الحالية، وكتبقى فالمستودع غير كمرجع للمنطق أعلاه وللاختبارات (`api/__tests__/notify.test.ts`، `tests/notify-contract.test.ts`). فالنموذج التجريبي (`build:demo`) المتصفح كيحاول يعيّط عليها عبر `VITE_NOTIFY_URL`، وفالمتجر الحقيقي (`VITE_DATA_MODE=supabase`) كيتجاهلها.

## 4. خطوات المالك (مرة وحدة، عند بدء المرحلة 4)

### أ. كلمة مرور تطبيق Gmail (5 دقائق)

1. ادخل حساب **bogacafe1@gmail.com** ← «إدارة حسابك» ← **الأمان**.
2. فعّل **التحقق بخطوتين** (إن لم يكن مفعّلاً).
3. ابحث عن **App passwords / كلمات مرور التطبيقات**، أنشئ واحدة باسم «BOGA site».
4. تظهر **16 حرفاً**: لا ترسلها فمحادثة عامة ولا فالمستودع؛ تُلصق مباشرة فـ Supabase → Edge Functions → Secrets (`GMAIL_APP_PASSWORD`).

### ب. مفتاح CallMeBot لواتساب (دقيقتان)

1. افتح صفحة CallMeBot الخاصة بواتساب (callmebot.com، قسم WhatsApp API) واتبع التعليمات الحالية: إضافة رقمهم فجهات الاتصال وإرسال الجملة المطلوبة **من رقم ‎+212 609-036378**.
2. يصلك رد على واتساب فيه **apikey**: هذا هو `CALLMEBOT_APIKEY` (يُلصق فنفس مكان الأسرار).

> CallMeBot خدمة مجانية لطرف ثالث مخصصة للتنبيهات الشخصية: مناسبة لتنبيه الإدارة الآن، وكتتذكر فصفحة الخصوصية. عند نمو الطلبات، الترقية هي **WhatsApp Cloud API** (رقم مخصص + حساب Meta Business).

القيم المسموحة والأسماء: `.env.example` (قسم `api/notify.ts`، وكيتحيّد مع نقل المنطق).
