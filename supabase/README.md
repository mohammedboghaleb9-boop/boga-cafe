# Supabase

Live project: `boga-cafe` (eu-west-3, PostgreSQL 17). State on 2026-10-27: 21 migrations, all applied; the sales are closed in the database (`salesOpen` unset).

- `migrations/`: the schema, one file per change, oldest first (`20260927000000_init.sql` … `20261021120000_catalog_showcase.sql`, then `20261027090000_quote_lines_for_sale.sql` and `20261027100000_policies_fk_indexes.sql`, both applied on 2026-10-27, the second through its SQL Editor block in `manual/` because it holds DROP POLICY). Never edit a file the live database has already applied: add a new one.
- `manual/`: SQL Editor blocks (`*.editor.sql`), their rollbacks (`*.rollback.sql`) and history repairs, for changes the apply tool cannot run (it hangs on `DELETE` and `DROP`). Each runs only with the owner's approval.
- `tests/`: SQL tests on a plain PostgreSQL 16 with pgTAP 1.3.2 (smoke, per-role permissions, catalog and showcase rules, parity with the site's `src/core`, stock races, lock stress):

  ```bash
  ./supabase/tests/run-local.sh   # superuser session; uses its own `boga_test` database only
  ```

- `functions/notify-outbox/`: the outbox sender (P5.1: Gmail and CallMeBot), called once a minute by the database; logic in `src/server/outbox.ts`; **not deployed yet**, its schedule is `manual/20261028090000_outbox_cron.sql` (`docs/09-notifications.md`).
- `functions/storefront/`: the Edge Function that receives orders and B2B requests (v11 deployed 2026-10-20). Its logic is `src/server/`, bundled by `npm run build:functions` into `functions/storefront/dist/index.js` (not committed).
- `seed.sql`: generated by `npm run seed:sql` from the prototype's examples, for new local or test databases only. Never run it on the live project.
- `config.toml`: local Supabase CLI settings.

Deploys (migrations, Edge Functions) come only from a branch merged into `main`, with the owner's approval.
